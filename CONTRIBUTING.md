# Contributing to TOU: Mira

Thanks for your willingness to contribute to this mod! We appreciate it.

To maintain the quality of the mod's codebase, please read the following guidelines.

## Requirements
- Before you submit a PR, please note that having a basic understanding of Unity and C# scripting is required. In the event questions are asked, your ability to answer them will factor into the final decision.
- Ensure that you are targeting the `dev` branch. PRs targeting `main` will be told to change targets, and if not acknowledged, will be closed. PRs targeting other branches are allowed, provided the reasoning is valid.
- Be nice. Entitled behaviour will result in your PR being prematurely rejected.

## Code
- Ensure that the code matches the format, order, and conventions already established within the codebase. Deviations aren't immediately disqualifying, but there needs to be a valid reason for them.
- Ensure that the code introduces little to no warnings. This doesn't mean that you should suppress all of them, so please actually follow through with the warnings. Suppression should only be reserved for warnings that don't make sense in context. Avoid suppressing warnings using `#pragma`, use `SuppressMessage` instead. This keeps the code clean, and the `Justification` field makes the existence of the suppression clear. If you *have* to use `#pragma`, add a justification in the comment for it. Rare situations might call for global warning suppression in a `.editorconfig` file.
- Do not blindly follow autocomplete suggestions from AI or Intellisense. IL2CPP has quirks that IDEs are unaware of, and seemingly ordinary changes WILL break the mod if added. These are easy to miss so please be vigilant.
- Test your code thoroughly. It is fine if the code is known to be buggy, but please mark your PR as a draft until any and all known bugs are resolved. Feel free to ask for help if you are stuck, we'd be happy to provide guidance. Code that has not been validated as tested will not be looked at until done so.
- If your project incorporates code from another source (whether written by a person or generated from existing code), credit must be given where required by the source's license.

## Content
- We will generally be reluctant to accept PRs that aim to make content changes, like adding/reworking roles and modifiers. It isn't because there's a lot to parse (although that does play a part), we want to avoid overwhelming releases with content without concentrating on bug squashing first. It is recommended that you make extension mods instead. We have [an extension template](https://github.com/AU-Avengers/TouExtensionExample) that you can make use of, or use [this MiraAPI template](https://github.com/All-Of-Us-Mods/MiraAPI/tree/master/MiraAPI.Example) if you want to make your own mod entirely.
- PRs porting content creator roles will be rejected. They are mostly commissioned content, and attempting to add them is just silly. However, you may develop and share ideas inspired by the content, provided you are explicit that it is not the actual version.
- **Absolutely no AI assets.** The moment it is discovered that the added assets are generated by AI, your PR will be rejected immediately. Either make assets yourself (or with the help of other contributors), or reuse assets from the publicly available [Google Drive of TOU assets](https://drive.google.com/drive/folders/1dipaLRMNV4iWz4DzH4UEL8dPgNRkr4S5?usp=drive_link).
  - If you are using code/assets not originally made by you, please credit the original creators.

## AI Policy
There is no denying that AI is here to stay, however, we will heavily regulate AI usage when it comes to writing code.
- **Pure AI generated PRs will be rejected immediately.** You will not be entitled to an explanation, because you yourself didn't even bother to work on your contribution.
- The code needs to be ***mostly*** human written. The code should be primarily written by you. If you are trying to implement a small fix/feature, don't bother using AI. Maintainers have the final say on when "too much" AI is used.
- **Transparency is a non-negotiable requirement.** You are expected to be open about your AI usage. The more open and honest you are, the higher your chances of having your PR merged.
  - Explicitly state which AI you used (eg, Claude, Gemini, ChatGPT).
  - Explain where the AI was used and for what reason.
- The incoming code should not contain AI comments. If any are generated, you are expected to replace them with human written comments so that others may actually understand what the code does.
- Be ready for scrutiny. If your PR contains AI generated code, you are responsible for it and are expected to know everything about it inside and out.

By submitting a PR, you acknowledge that you have read and agreed to the above guidelines.
